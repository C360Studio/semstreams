## Problem statement

a drain-once binding around the exact `jetstream.ConsumeContext`, and an observer goroutine that reacts to the first
`OwnerStopRequired` result by recording the fatal and draining that handle — is spelled once per agentic component.
The #1249 design copies it a sixth time into `agentic/agentrun`. Owner ruling 2026-09-19 (#1341): "agree - if we have
a legit abstraction lets add it after L3 so L4 does not need to do it all over." This inventory measures what exists
before any target state is drafted.

## Adopter seam inventory

Run because the package's home decides whether a surface is reached from outside. Answered as a component author in
a sister repo who has never opened `delivery_owner.go` and is migrating off `ConsumeWithHeartbeat` because the #1249
layer deletes it (`docs/operations/migration-beta162-to-beta163.md:1146-1151`).

**1. What must they know today (typed API, no package)?** Six facts: (a) construct the latch before `Consume` so a
fatal reported before the handle returns is buffered, not lost (spec `:602`); (b) latch only on `OwnerStopRequired`,
never on a terminal-method error (`:589-590`); (c) closed admission runs no work, heartbeat, or terminal method
(`:603`); (d) drain the exact handle outside the callback, never inside it (`:604-605`); (e) join the observer during
Stop (`:605`); (f) declare each refusal with a log line and a lane-labelled counter (`:606-608`). Six is a design
finding — more than two.

**2. What happens if they do nothing?** The callback keeps running work after heartbeat control is lost: duplicate
effects on redelivery, no health signal, the handle never drained. Silent. The migration note (`:87-88`) tells them
to "close admission and stop the exact retained consume handle" and hands them nothing to do it with.

**3. Where do they find out?** Doc (`docs/concepts/33-semantic-settlement.md:89`; the migration note) → a finding for
a correctness fact. There is no compile, boot, or typed-runtime signal that a lane consumed without a latch.

**4. What should they have to know?** Nothing beyond "consume under an admission": construct one, pass it, retain the
binding. That is what the in-tree package gives the five owners. Whether it is exported is the one open question
this inventory surfaces for the owner: present external consumers are zero (§ 4), `openspec/project.md` admits a
package on two independent product reuses or a recorded usability gap, and semdev's forced migration is exactly
such a gap — but a future one.

**Prefer observation to prediction.** The typed API already observes the fatal (the framework decides
`OwnerStopRequired`); what it asks the adopter to build is the REACTION. The package is the framework absorbing that
reaction; no value is predicted by the caller.

Surfaces this change touches that ARE reached from outside: none if the home is `internal/`. If the home is `natsclient`
or `pkg/`, the exported symbols are a Tier 1 widening and `scripts/api-compat.sh` reports them under ADDED (RC-6
walked path owed).
